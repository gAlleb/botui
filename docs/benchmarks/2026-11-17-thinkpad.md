# ThinkPad comparison, 17 November 2026

This is a measured comparison of BOTUI **v0.1.20 / 04dfb779** and the official
Bookokrat **v0.3.14 GNU** binary, not a comparison with Bookokrat's unreleased
main branch. It covers the books and operations below, not every supported
format or a general ranking of the readers.

## Reproduction conditions

- ThinkPad X13, Intel i5-1245U, 12 logical CPUs, 16 GiB RAM, Linux 6.18.62.
- Separate temporary HOME/XDG profiles; no changes to the user's library,
  positions, annotations, terminal configuration or desktop.
- Native runs: private headless Mango, Kitty, software rendering, 1600×1000,
  CaskaydiaMono Nerd Font 14, 145×43 cells. Both readers and their terminal use
  CPUs 0–1 and nice 10 to keep this laptop responsive. No concurrent builds.
- Single-column EPUB view. BOTUI uses width 110, framed Zen and Gruvbox Dark;
  Bookokrat uses framed Zen and Oceanic Next. PDF is fitted to the viewport
  (Bookokrat scale 0.46). The applications' layout and colors are not identical.
- Three fresh-profile launches per application/book, alternating application
  order. The OS file cache is **not** cleared. These are warm-filesystem runs.
- The terminal is ready before the reader's launch timer starts. A visible
  progress footer marks EPUB readiness; PDF also requires actual page pixels.
  This does not guarantee that all off-screen illustrations have finished loading.
- RSS/PSS is sampled from `/proc` 700 ms after readiness. Reader RSS excludes
  Kitty and its helper processes; raw results retain them separately.
- Failed harness setup probes are excluded. Bookokrat search requires Enter to
  execute the query and another Enter to jump; its PDF pages use Right/Left.

Raw measurements: [native runs and repeated reading](2026-11-17-native.json),
[BOTUI PTY layout runs](2026-11-17-pty.json). KiB and MiB use powers of 1024.
The [native audit scripts and commands](2026-11-17-tools/README.md) are retained
with machine-local paths replaced by environment variables.

## First visible screen

Medians of three runs; memory is the reader process RSS.

| Book | BOTUI ready | Bookokrat ready | BOTUI RSS | Bookokrat RSS |
|---|---:|---:|---:|---:|
| Illustrated Amber EPUB | 854 ms | 644 ms | 120.3 MiB | 15.7 MiB |
| Ayurveda EPUB | 653 ms | 599 ms | 86.5 MiB | 15.8 MiB |
| Lessons PDF | 1,491 ms | 3,160 ms | 56.3 MiB | 101.8 MiB |

Bookokrat has a clear startup-memory advantage on these EPUBs. BOTUI prepares
the continuous book layout; Bookokrat initially displays a short chapter. This
explains why a first-screen comparison needs a second measurement during reading.
On this PDF, BOTUI starts faster and uses less memory. These results do not
support the claim that either reader is always faster or lighter.

## Repeated reading and storage

### Illustrated EPUB

Both readers search for `лунных`, jump to the first result in chapter ten, then
perform five cycles of three PageDown and three PageUp operations. The same
input is used, but each reader's page capacity differs.

| Reader | After opening the result | After first cycle | After fifth cycle |
|---|---:|---:|---:|
| BOTUI | 135.1 MiB | 136.1 MiB | 136.1 MiB |
| Bookokrat | 85.2 MiB | 93.7 MiB | 93.7 MiB |

Both reach a plateau in this scenario. Bookokrat's disk cache contains 145 files
totaling 54,308,239 bytes (extracted images); BOTUI's cache contains one 203-byte
fingerprint. The counts and bytes remain unchanged through the cycles. This
does not mean extracted images are a leak: they avoid extracting them again.

An additional BOTUI PTY run repeats 18 spreads forward/backward and two resizes
per cycle. RSS stays at 153.1 MiB for all five cycles after initial warming.

### PDF

Five cycles from physical page 1 to page 9 and back. The table separates the
reader's memory from the terminal's memory.

| Process | Open | Cycle 1 | Cycle 3 | Cycle 5 |
|---|---:|---:|---:|---:|
| BOTUI baseline | 61.6 MiB | 144.8 MiB | 150.4 MiB | 150.4 MiB |
| Kitty hosting BOTUI | 229.5 MiB | 261.9 MiB | 306.2 MiB | 349.6 MiB |
| Bookokrat | 102.0 MiB | 446.0 MiB | 534.2 MiB | 525.3 MiB |
| Kitty hosting Bookokrat | 217.3 MiB | 317.2 MiB | 365.2 MiB | 377.3 MiB |

Neither reader writes a PDF page cache to disk in this run. Bookokrat's debug
log grows by roughly 150 KB. Its memory fluctuates around a plateau; BOTUI's
own page cache is bounded, but its Kitty memory keeps growing in this run.
Investigation found that discarded ratatui-image Kitty protocols do not release
their terminal uploads. This is an application graphics-lifetime issue, not
evidence that the PDF raster cache itself grows without limit.

## Audit follow-up

Confirmed gaps addressed after these baseline measurements:

- PDF selection can address individual characters with optional Poppler GI,
  including intrinsically rotated pages. Without it, word selection remains
  available. Canonical text offsets remain unchanged for saved annotations.
  Internal page links and confirmed external links now work. Native Kitty checks
  copied part of `interoperability` in both BOTUI and Bookokrat; both followed
  page 1→3 and an external link. Different drag endpoints are not an accuracy
  ranking. Partial-word annotation import also works without GI when the quote
  uniquely identifies the range inside the stored rectangles.
- Vim gains `W/B/E`, `f/F/t/T`, `;`/`,`, WORD and quote/bracket objects. The new
  permanent smoke test covers 28 cases. Native Bookokrat checks confirmed its
  core motions, with narrower differences in counted finds, repeated `t`,
  finding spaces and angle-bracket objects. The existing `yiw` boundary for
  `Alpha.one` remains different: BOTUI selects `Alpha.one`, Bookokrat `Alpha`.
- Lookup dialogs fit their content and omit irrelevant language controls.
  Selection behind a context menu remains legible instead of being dimmed twice.
- Fingerprints are capped at 4,096 files / 4 MiB; each external-viewer image
  export directory at 256 files / 128 MiB. Old recognized regular cache files
  are removed first; the active export is retained even if it exceeds the cap.
  Saved books, reading positions, notes and unknown files are excluded.
- Kitty image uploads have explicit ownership and are released when the last
  owner drops them. Active/cached images are retained. Managed uploads use
  compressed data instead of shared-memory files, avoiding files left behind
  by preloaded images that were never displayed.

Changes are validated separately from baseline performance. Foot is unavailable
on this machine. The `synctex` utility is also absent: its command integration
is exercised by the existing fixture, not a live TeX compilation comparison.
Ordinary BookOrbit annotation exchange is checked against the
local server fixture, not the user's live server; page-wide and cross-document
annotation cases remain separate planned work.

## Final release-build validation

The changed host release is **24,034,232 bytes**, SHA-256
`bb0c569c3268902eb897e8ad9a79cba5e23e4cf55bd5a1959fd6957b67b01b0e`:
113,824 bytes (+0.48%) above the baseline, with no newly added transitive crate.

Five PDF cycles on this build give the following RSS values. Other isolated
functional tests ran concurrently, but no build; these samples validate
retention, not interaction speed. [Raw validation](2026-11-17-validation.json).

| Process | Open | Cycle 1 | Cycle 3 | Cycle 5 |
|---|---:|---:|---:|---:|
| Changed BOTUI release | 63.2 MiB | 161.9 MiB | 166.8 MiB | 166.8 MiB |
| Kitty hosting changed BOTUI | 230.1 MiB | 248.7 MiB | 248.7 MiB | 248.7 MiB |

The reader retains roughly 16 MiB more than the baseline in this case, while
Kitty retains roughly 101 MiB less after five cycles and no longer grows each
cycle. Compressed uploads now live in the reader rather than shared-memory
files; this is not a claim that every process becomes smaller. The PDF raster
is pixel-identical after all 80 page turns. There are no PDF cache files and
the two position/state files remain at 194 bytes after the first cycle.

On the illustrated Amber EPUB, the uncovered illustration stays pixel-identical
while footnote `[33]` is open. The whole frame is identical after closing it,
and again after going forward/back. The release also passes search, selected
paragraph, resize and reopen checks on the real book with images on and off.

Final automated checks: formatting, Clippy and **281 Rust tests passed**;
all **47 terminal smoke scripts passed**. The annotation-sync script needed
one explicit `viw` instead of `v`: character selection now starts with one
character. Its exact `Lighthouse`/page/rectangle assertions were retained and
the complete sync script passed on rerun. The remaining scripts completed
without a failure, including Sixel popup restoration and actual SVG rendering.
