# BOTUI architecture

**English** · [Русский](architecture.ru.md)

Readers can resume a BookOrbit edition, browse a local library without an account, open a file by path or connect to an OPDS catalog. A BookOrbit server can also serve as an OPDS source. Each source supplies a file to the same reader. The file format determines how BOTUI reads its contents, and the terminal determines how it displays them.

## Modules and responsibilities

| Module | Responsibilities |
|---|---|
| Application and input (`crates/app`) | File selection, focus, commands, menus, colors and restoring the terminal on exit. The Rust UI uses Ratatui and Crossterm. As in omtalk, mouse and keyboard input invoke the same actions, and the wheel scrolls the region under the pointer. |
| Book formats (`crates/formats`) | Opens the EPUB ZIP, locates its OPF package and reads XHTML chapters in spine order using zip, roxmltree and scraper. A separate FB2 parser reads headings and paragraphs from the main body and handles UTF-8, UTF-16 and Windows-1251. Bookokrat informed the rendering goals and repy provided FB2 examples. Full HTML/CSS layout is outside the parser’s scope. |
| Reading core (`crates/core`) | Tracks logical reading positions, wraps text by terminal cell width and paginates it. A spread displays two consecutive pages of the same text. The core can be tested without a terminal. |
| Storage (`crates/store`) | Saves local reading position, view and palette. A file’s SHA-256 identifies its atomically replaced record. Renaming the file preserves its state. Two different files of the same edition have separate records. |
| Native BookOrbit source (`crates/bookorbit`) | Handles authentication, server IDs, API errors, the dashboard, author and series indexes, catalog, libraries, personal collections, edition files and thumbnails. Index totals cover the full result set. Volumes in a series are requested in `seriesIndex` order. The shelf and the diagnostic CLI use this adapter. |
| OPDS (`crates/opds`) | Handles catalog entry points, navigation and acquisition feeds, alternate formats, pagination and optional search. The adapter follows the [OPDS specification](https://specs.opds.io/opds-1.2). See also [repy’s OPDS model](https://github.com/newptcai/repy/blob/0a3c3a2063af87fd5d0824cb4588ccfd043cdcf4/src/opds.rs). |
| Fixed-layout pages (`crates/fixed`, `crates/app/src/scan`) | Renders PDF or DjVu pages at a requested size using Poppler or DjVuLibre in a separate process. Local files can be read without a server. Upstream references include [Bookokrat’s background rendering and Kitty support](https://github.com/bugzmanov/bookokrat/tree/v0.3.14/src/pdf) and [BookOrbit’s WebP endpoint for DjVu pages](https://github.com/bookorbit/bookorbit/blob/main/docs/DJVU_READER.md). |

These are independently testable modules in one application. BOTUI defines shared interfaces as implementations need them and currently has no public ABI for loadable plugins.

The `botui` executable opens books from each source. The separate `botui-catalog` command can query BookOrbit collections without starting the TUI. Grids and lists share the book and file model in `crates/app/src/catalog.rs`. The shelf converts native responses in `shelf/native.rs` and Atom entries in `shelf/opds.rs`. The local grid uses the file path as its own key and passes the same card renderer a book. Server collection types and OPDS acquisition links stay within their respective adapters. Opening a single local file requires no catalog implementation.

The official client and server define the BookOrbit contracts for [collections](https://github.com/bookorbit/bookorbit/blob/v3.6.0/server/src/modules/collection/collection.controller.ts) and [reading progress](https://github.com/bookorbit/bookorbit/blob/main/server/src/modules/book/reading-progress.controller.ts). Fixtures and a local HTTP server exercise version-specific responses. [Bookokrat bookmarks](https://github.com/bugzmanov/bookokrat/blob/v0.3.14/src/bookmarks.rs) and [repy’s KOReader progress support](https://github.com/newptcai/repy#koreader-progress-sync) use their own position formats. BookOrbit sync requires a position that identifies the location in the specific edition.

## Opening books and saving positions

- A local book opens by path. The first time a BookOrbit edition opens, the shelf downloads it by `fileId` and keeps it for subsequent and offline reading. A sidecar records the edition ID, account and position for sync. For OPDS, the adapter maps catalog entries to acquisition links. Opening downloads a temporary file. **Save offline** keeps a copy in OPDS downloads.
- The shelf requests visible covers with two background workers and a per-connection LRU cache of 48 results. An explicit missing-cover flag skips the request. The fallback for every source is BOTUI’s cloth binding with a botanical ornament. The series or title determines its color. The graphical shelf and external viewer share the artwork. The text fallback draws the title in terminal cells. Mouse hit testing uses the rectangles of the cards actually drawn.
- The text reader saves a block and byte offset in normalized UTF-8. A separate map relates displayed passages to the source XHTML, spine and original UTF-16 offsets. EPUB mapping requires a unique matching block. FB2 mapping follows Foliate’s conversion of the main prose in the first body. Unsupported locations, such as some poems and notes, remain unresolved. Bookmarks, notes, search and the publisher’s contents use the same local anchor. Joining hard-wrapped print lines for display preserves those anchors. Set `preserve_printed_lines` to keep the original line breaks.
- Native sync reads the record for the edition’s `fileId` and checks it again before saving. Where the server supports conditional updates, `editedAt` identifies the version the reader opened and a `superseded` reply signals a conflict. Changing the theme, window size or page mode preserves the reading position. The local copy survives a conflict or a failed request. OPDS reading does not write progress to BookOrbit.
- PDF and DjVu use physical page numbers, a cancellable rasterizer process and a bounded cache for the current spread and its neighbors. The same terminal graphics layer draws pages and covers. Each format needs only its own rendering engine. Direct Kitty output was checked at the pixel level. In tmux the reader probes the attached terminal through passthrough. Kitty can display full-resolution images, with a cell-based fallback when graphics are unavailable. Unsupported formats remain visible on the shelf.
- The terminal determines cell size and font. The regular reader displays a contents sidebar and a short command bar. Zen displays just the book. In narrow windows, `O` opens the contents. The shelf shows titles, covers, formats and progress, with persistent navigation for libraries and collections when space allows.

## Verification and limitations

Terminal tests using tmux and local HTTP fixtures cover the native catalog, OPDS 1.x/Atom and OPDS 2/JSON with separate authentication, accounts with no collections, edition selection, covers and placeholders, position conflicts, and PDF/DjVu spreads. A Kitty session on an isolated desktop verified covers from local EPUBs. The `cfi-probe` example and `scripts/check-foliate.mjs` checked Rust ↔ Foliate position conversion on the Itorra collection. All 11 sampled positions in each of EPUB and FB2 returned to the same block and byte.

Additional cases cover remote search beyond the first result page, the current and recent shelves, bookmarks without an address and creating and deleting server bookmarks. An offline scenario saves a book, signs out, reads without a server request and checks the conditional update after signing in. A local scenario sets the library root from the UI, finds a file several levels below it and restores the root after restart. A Gesar EPUB was used to check NCX navigation, reflow in both columns, joining a split word and restoring the layout. Scan search requires a text layer. Scan bookmarks, notes and Markdown exports identify the physical page. In every format, `S` shows local sessions and time spent with the book open.

Links and illustrations retain their source block. In illustrated books, a local raster plate can fill its own page. The reader can follow a link within the document, open a footnote in another XHTML file, display an embedded binary resource or offer an external web link. In EPUB and FB2, `I` lists these resources. Reading does not fetch images from websites.

The OPDS client handles Atom and JSON, including groups, facets and search templates. The format parser attaches links, images and tables to source blocks. The core wraps text and places illustrations in reading order while preserving BookOrbit addresses. Text scrolling advances the top line. For scans a separate module computes which parts of each page are visible and preloads the next two pages. The local scroll offset is stored separately from the page number sent to the server.

The start screen owl uses a 22 × 32 sprite. Each pixel identifies a palette role. Two rows of pixels share one terminal cell. Kitty and Alacritty display the same half-block characters. The Terminal theme uses ANSI palette slots.

Terminal styling uses default SGR colors and ANSI slots. Opaque terminal paper needs the current background RGB, queried through OSC 11. Named interface palettes and book paper can be chosen independently of each other and of tools such as pywal or matugen. The catalog tree has independently collapsible groups. Book details load in the background while edition click targets stay in place. Changing reading status and resetting reading state use their respective API endpoints.

The local folder tree reads only the immediate subfolders of an expanded branch. Opening a path expands its ancestors. Searching the whole library root runs separately in the background. Dragging the divider changes the widths of the two panels.

For the individual scenarios, see the [verification checklist](checklist.md).
