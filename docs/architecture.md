# botui: устройство терминальной читалки

Основной сценарий — открыть свою библиотеку BookOrbit и продолжить книгу. Второй вход — передать локальный файл без сети и аккаунта. Обычный OPDS-каталог подключается отдельным адаптером; им может быть и тот же BookOrbit. Источник отвечает за доступ к книге, формат — за её содержимое, терминал — за способ показа.

## Модули и границы

| Область | Что ей принадлежит | Стартовая реализация и ориентир |
|---|---|---|
| Приложение и ввод (`crates/app`) | Выбор файла, фокус, команды, меню, цвета, восстановление терминала после выхода | Rust, Ratatui и Crossterm. Из omtalk берём поведение: мышь и клавиши вызывают общие действия, колесо действует в своей области. Виджеты чата не переносим. |
| Книжные форматы (`crates/formats`) | Определить содержимое EPUB, найти OPF и пройти spine в порядке чтения, преобразовать главы в текстовые блоки | Работаем с настоящим ZIP и XHTML (zip, roxmltree, scraper). FB2 использует отдельный XML-разбор: заголовки и абзацы основного тела, кодировки UTF-8/UTF-16 и Windows-1251. Из Bookokrat берём ориентиры по качеству отображения, из repy — примеры работы с FB2. Полного HTML/CSS-рендера в первом срезе нет. |
| Ядро чтения (`crates/core`) | Логическое место в книге, переносы по ширине терминальных ячеек, страницы, разворот | Своё небольшое ядро, тестируется без терминала. Разворот — две соседние страницы одного потока. |
| Хранение (`crates/store`) | Место чтения локального документа, выбранный вид и палитра | Отдельная атомарно заменяемая запись на SHA-256 файла. Переименование её не теряет; разные файлы одного издания пока имеют разные записи. |
| Родной источник (`crates/bookorbit`) | Вызовы API, серверные идентификаторы и ответы об ошибках | Вход, общий каталог, библиотеки, личные коллекции, страницы списка книг, получение выбранного файла и миниатюры. Используется экраном полки и отдельной диагностической командой. |
| OPDS (`crates/opds`) | Вход в каталог, ленты навигации и выдачи, несколько ссылок на форматы, постраничная загрузка и необязательный поиск | Самостоятельный адаптер. Модель [repy](https://github.com/newptcai/repy/blob/0a3c3a2063af87fd5d0824cb4588ccfd043cdcf4/src/opds.rs) полезна как пример; основу контракта определяет [спецификация OPDS](https://specs.opds.io/opds-1.2). |
| Фиксированные страницы (`crates/fixed`, `app/src/scan`) | PDF/DjVu → изображение страницы заданного размера; затем передача изображения терминалу | Poppler и DjVuLibre в отдельном процессе. Ориентир по фоновым запросам и работе с Kitty — реализация [Bookokrat](https://github.com/bugzmanov/bookokrat/tree/v0.3.14/src/pdf). На подходящих версиях BookOrbit [страницы DjVu можно получать как WebP](https://github.com/bookorbit/bookorbit/blob/main/docs/DJVU_READER.md). Для локального файла сервер не нужен. |

Модули здесь — части одного приложения, которые можно независимо проверять. Публичный ABI для загружаемых плагинов пока не нужен. Там, где ещё нет двух реализаций, не фиксируем интерфейс заранее.

Основной бинарник `botui` ведёт с полки BookOrbit или из локальной папки в одну читалку. Команда `botui-catalog` позволяет проверить родной запрос коллекций отдельно от TUI. Серверный тип коллекции живёт только в адаптере. Полка показывает коллекцию, книгу с вариантами файла и продолжение списка, ему не нужны токен, HTTP-адрес или формат ответа BookOrbit. OPDS-ссылки остаются внутри второго адаптера, а одиночный локальный файл вообще не должен реализовывать API каталога.

На [чтение коллекций](https://github.com/bookorbit/bookorbit/blob/main/server/src/modules/collection/collection.controller.ts) и [сохранение позиции](https://github.com/bookorbit/bookorbit/blob/main/server/src/modules/book/reading-progress.controller.ts) ориентируемся по коду официального клиента и сервера. Эти контракты могут меняться вместе с сервером; для конкретной версии проверяем ответ фикстурой и локальным HTTP-стендом. Bookokrat хранит собственные [закладки](https://github.com/bugzmanov/bookokrat/blob/v0.3.14/src/bookmarks.rs), repy предлагает [чтение позиции KOReader](https://github.com/newptcai/repy#koreader-progress-sync); ни один из этих механизмов не заменяет обмен точной позицией с BookOrbit.

## Путь открытия и позиции

- У локального файла уже есть путь. Для BookOrbit полка получает временный файл по fileId, для OPDS — по выбранной acquisition-ссылке. Модель OPDS не знает ничего о маршрутах BookOrbit. Для неё идентификаторы строк и ссылки связывает адаптер в приложении. Временный файл живёт до закрытия книги.
- Полка получает только видимые обложки: два фоновых задания, кэш LRU на 48 результатов, отдельный кэш на подключение. Флаг отсутствующей обложки пропускает запрос. При отсутствии картинки TUI создаёт собственный переплёт; это адаптация принципа [BookCoverPlaceholder из BookOrbit](https://github.com/bookorbit/bookorbit/blob/6ad1445dab35757164ed3bf31e83caeb6ba24ad2/client/src/features/book/components/BookCoverPlaceholder.vue), не загрузка SVG из веб-клиента. Сетка хранит прямоугольники реально нарисованных карточек для обработки мыши.
- Текстовый пейджер сохраняет блок и байт нормализованного UTF-8, не экранный номер страницы. Отдельная карта сопоставляет показанные фрагменты со структурой XHTML, spine и исходными UTF-16-смещениями. EPUB использует однозначно совпавшие блоки; FB2 воспроизводит структуру основной прозы первого body в конвертере Foliate. Неподдержанные адреса, например сложное стихотворение или примечание, не подменяются соседним адресом. Текстовые закладки, поиск и оглавление по заголовкам используют один и тот же локальный якорь.
- Native API читает запись конкретного fileId. Перед сохранением перечитывается исходная запись. Поле editedAt ограничивает запись версией, которую клиент видел при открытии; ответ superseded означает конфликт. Поддержка защиты зависит от серверного API. Изменение темы, ширины окна или режима страниц само по себе не двигает позицию. При ошибке или конфликте локальная копия остаётся. У OPDS нет неявной записи в BookOrbit.
- PDF и DjVu проходят отдельный путь: номер физической страницы, подготовка растра в отменяемом процессе, ограниченный кэш текущего разворота и соседей. Декодер передаёт изображение тому же терминальному слою, который рисует обложки. Нужен только установленный движок соответствующего формата. Прямой Kitty проверен с настоящим пиксельным выводом; в tmux используется совместимый вариант. Неподдерживаемый формат не скрывается с полки.
- Размер и шрифт ячейки определяет терминал. В текстовом режиме рамка, библиотека и команды видны только по запросу. На полке, наоборот, используются заголовки, обложки, подписанные форматы и процент чтения, а при достаточной ширине — постоянная левая колонка библиотек и коллекций.

## Что проверено и где остаются границы

Тесты через tmux и локальные HTTP-серверы покрывают родной каталог, OPDS 1.x/Atom с независимой авторизацией, доступность полки без коллекций, выбор файла, обложку и заглушку, позиции, отказ от перезаписи чужого прогресса, чтение и разворот PDF/DjVu. В отдельном виртуальном рабочем столе снят реальный Kitty с обложками из локальных EPUB. Обмен Rust ↔ Foliate проверяется `scripts/check-foliate.mjs` с примером `cfi-probe`: для сборника Иторра 11 позиций EPUB и 11 FB2 вернулись в тот же блок и байт. Это проверка выборки, не всех вариантов EPUB и FB2.

Остаётся ручная проверка на том же файле между личным BookOrbit, TUI и iPhone. Не реализованы офлайн-загрузки с очередью синхронизации, OPDS 2, полноценная HTML/CSS-вёрстка с иллюстрациями и сносками, текстовый поиск или аннотации внутри сканов. Не все функции [Bookokrat](https://bugzmanov.github.io/bookokrat/index.html) являются функциями botui.
