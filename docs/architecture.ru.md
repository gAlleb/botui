# botui: устройство терминальной читалки

[English](architecture.md) · **Русский**

Основной сценарий — открыть свою библиотеку BookOrbit и продолжить книгу. Локальная папка — независимая библиотека с навигацией, поиском и историей, без сети и аккаунта. Отдельный файл тоже можно открыть напрямую. Обычный OPDS-каталог подключается отдельным адаптером; им может быть и тот же BookOrbit. Источник отвечает за доступ к книге, формат — за её содержимое, терминал — за способ показа.

## Модули и границы

| Область | Что ей принадлежит | Стартовая реализация и ориентир |
|---|---|---|
| Приложение и ввод (`crates/app`) | Выбор файла, фокус, команды, меню, цвета, восстановление терминала после выхода | Rust, Ratatui и Crossterm. Из omtalk берём поведение: мышь и клавиши вызывают общие действия, колесо действует в своей области. Виджеты чата не переносим. |
| Книжные форматы (`crates/formats`) | EPUB, spine, исходные адреса XHTML и разбор FB2 | Для оформленной главы хранит XHTML с привязкой к исходным узлам. Стили читает из архива EPUB. Размеченный TeX переводит в MathML. Разбор FB2 поддерживает UTF-8, UTF-16 и Windows-1251. |
| Ядро чтения (`crates/core`) | Перенос текста, вёрстка CSS и пагинация | Встроенный Blitz рассчитывает геометрию оформленных глав. Метрики терминальных ячеек связывают координаты строк и таблиц с адресами фрагментов книги. Один пейджер обслуживает страницу, разворот и прокрутку. |
| Хранение (`crates/store`) | Место чтения локального документа, выбранный вид и палитра | Отдельная атомарно заменяемая запись на SHA-256 файла. Переименование её не теряет; разные файлы одного издания пока имеют разные записи. |
| Родной источник (`crates/bookorbit`) | Вызовы API, серверные идентификаторы и ответы об ошибках | Вход, дашборд, справочники авторов и серий, общий каталог, библиотеки, личные коллекции, получение выбранного файла и миниатюры. Справочники возвращают total для всего результата. Книги серии запрашиваются с сортировкой seriesIndex. Используется экраном полки и отдельной диагностической командой. |
| OPDS (`crates/opds`) | Вход в каталог, ленты навигации и выдачи, несколько ссылок на форматы, постраничная загрузка и необязательный поиск | Самостоятельный адаптер. Модель [repy](https://github.com/newptcai/repy/blob/0a3c3a2063af87fd5d0824cb4588ccfd043cdcf4/src/opds.rs) полезна как пример; основу контракта определяет [спецификация OPDS](https://specs.opds.io/opds-1.2). |
| Фиксированные страницы (`crates/fixed`, `app/src/scan`) | PDF/DjVu → изображение страницы заданного размера; затем передача изображения терминалу | Poppler и DjVuLibre в отдельном процессе. Ориентир по фоновым запросам и работе с Kitty — реализация [Bookokrat](https://github.com/bugzmanov/bookokrat/tree/v0.3.14/src/pdf). На подходящих версиях BookOrbit [страницы DjVu можно получать как WebP](https://github.com/bookorbit/bookorbit/blob/main/docs/DJVU_READER.md). Для локального файла сервер не нужен. |

Модули здесь — части одного приложения, которые можно независимо проверять. Публичный ABI для загружаемых плагинов пока не нужен. Там, где ещё нет двух реализаций, не фиксируем интерфейс заранее.

Основной бинарник `botui` ведёт с полки BookOrbit или из локальной папки в одну читалку. Команда `botui-catalog` позволяет проверить родной запрос коллекций отдельно от TUI. Серверный тип коллекции живёт только в адаптере. Для сетки и списка используется общая модель книги и её файлов в app/src/catalog.rs; преобразование из ответов BookOrbit находится в shelf/native.rs, из Atom — в shelf/opds.rs. Локальная сетка передаёт той же карточке путь как собственный ключ и не импортирует типы клиента BookOrbit. OPDS-ссылки остаются внутри второго адаптера, а одиночный локальный файл вообще не должен реализовывать API каталога.

На [чтение коллекций](https://github.com/bookorbit/bookorbit/blob/v3.6.0/server/src/modules/collection/collection.controller.ts) и [сохранение позиции](https://github.com/bookorbit/bookorbit/blob/main/server/src/modules/book/reading-progress.controller.ts) ориентируемся по коду официального клиента и сервера. Эти контракты могут меняться вместе с сервером; для конкретной версии проверяем ответ фикстурой и локальным HTTP-стендом. Bookokrat хранит собственные [закладки](https://github.com/bugzmanov/bookokrat/blob/v0.3.14/src/bookmarks.rs), repy предлагает [чтение позиции KOReader](https://github.com/newptcai/repy#koreader-progress-sync); ни один из этих механизмов не заменяет обмен точной позицией с BookOrbit.

## Путь открытия и позиции

- Локальный файл открывается по пути. При первом открытии издания BookOrbit полка скачивает файл по `fileId` и сохраняет его для повторного и офлайн-чтения. Рядом с файлом хранятся идентификатор издания, привязка к аккаунту и позиция для синхронизации. Для OPDS адаптер связывает строки каталога со ссылками acquisition. При обычном открытии файл временный, а команда Save offline сохраняет издание в каталоге загрузок OPDS.
- При переходе в раздел каталога открытая полка видна до получения ответа. Если запрос затянулся, внизу появляются ход загрузки и кнопка отмены. Новый раздел занимает место предыдущего, когда готов.
- Два фоновых задания загружают видимые обложки. На каждое подключение приходится кэш на 48 результатов. Название сразу видно под отведённым для картинки местом. Если каталог сообщает, что обложки нет, запрос пропускается. Для недоступной обложки BOTUI рисует собственный переплёт, цвет которого определяет серия или название. Полка и внешний просмотрщик используют один рисунок. В текстовом терминале надпись выводится ячейками.
- При смене ширины EPUB читалка сначала верстает главы, видимые с сохранённого места. Фоновое задание использует готовые строки разворота для подсчёта страниц во всей книге. Следующее изменение размера отменяет устаревшее задание. Поиск и листание используют полный индекс.
- Текстовый пейджер сохраняет блок и смещение UTF-8. В EPUB диапазон видимого текста связан с узлом исходного XHTML, позицией в spine и смещением UTF-16 для BookOrbit. Для обычного текста также используется сопоставление абзацев. Закладки, поиск, сноски и история работают с тем же адресом. В FB2 адреса соответствуют преобразованию Foliate. Настройка `preserve_printed_lines` сохраняет издательские переносы.
- Native API читает запись конкретного fileId. Перед сохранением перечитывается исходная запись. Поле editedAt ограничивает запись версией, которую клиент видел при открытии; ответ superseded означает конфликт. Поддержка защиты зависит от серверного API. Изменение темы, ширины окна или режима страниц само по себе не двигает позицию. При ошибке или конфликте локальная копия остаётся. У OPDS нет неявной записи в BookOrbit.
- PDF и DjVu проходят отдельный путь: номер физической страницы, подготовка растра в отменяемом процессе, ограниченный кэш текущего разворота и соседей. Декодер передаёт изображение тому же терминальному слою, который рисует обложки. Нужен только установленный движок соответствующего формата. Прямой Kitty проверен с настоящим пиксельным выводом; в tmux читалка опрашивает внешний терминал через passthrough. В Kitty доступны полноцветные изображения в пикселях. Если графика недоступна, читалка рисует картинку символами. Неподдерживаемый формат не скрывается с полки.
- Размер и шрифт ячейки определяет терминал. Обычное чтение показывает боковое оглавление и короткую строку команд, Zen оставляет только текст. Если окно слишком узкое для боковой панели, оглавление доступно по O. На полке, наоборот, используются заголовки, обложки, подписанные форматы и процент чтения, а при достаточной ширине — постоянная левая колонка библиотек и коллекций.

## Что проверено и где остаются границы

Тесты через tmux и локальные HTTP-серверы покрывают родной каталог, OPDS 1.x/Atom и OPDS 2/JSON с независимой авторизацией, доступность полки без коллекций, выбор файла, обложку и заглушку, позиции, отказ от перезаписи чужого прогресса, чтение и разворот PDF/DjVu. В отдельном виртуальном рабочем столе снят реальный Kitty с обложками из локальных EPUB. Обмен Rust ↔ Foliate проверяется `scripts/check-foliate.mjs` с примером `cfi-probe`: для сборника Иторра 11 позиций EPUB и 11 FB2 вернулись в тот же блок и байт. Это проверка выборки, не всех вариантов EPUB и FB2.

Дополнительные сценарии проверяют удалённый поиск за границей первой выдачи, две личные полки, закладку без адреса и создание/удаление серверной закладки. Отдельный тест сохраняет книгу, выходит из аккаунта, читает копию без запросов к серверу и проверяет условную запись после входа. Локальный сценарий задаёт корневую папку из интерфейса, находит файл несколькими уровнями ниже и проверяет восстановление после перезапуска. На реальном EPUB о Гесаре проверены переходы по NCX, переразбивка обеих страниц, соединение разорванного слова и точный возврат раскладки. Для PDF/DjVu поиск использует текстовый слой; распознавания изображений нет. Закладки и заметки в сканах адресуют физическую страницу; Markdown-экспорт указывает её номер. Во всех форматах S показывает количество локальных сеансов и время с открытой книгой.

Ссылки и иллюстрации привязаны к исходному блоку. В книгах, состоящих из иллюстраций, локальные растровые пластины могут образовывать самостоятельные страницы. Формат разрешает ссылки в адрес того же документа, дополнительный XHTML сноски, двоичный ресурс внутри книги или URL веб-сайта. Текст, изображение или переход открываются по выбору из I; чтение не обращается к сайтам за изображениями. EPUB и FB2 используют один экран.

Клиент OPDS понимает Atom и JSON, включая группы, фасеты и шаблоны поиска. В `formats` ссылки, изображения и таблицы привязаны к исходным блокам. `core` переносит текст и ставит иллюстрации в поток без изменения адресов BookOrbit. Текстовый режим Scroll перемещает верхнюю строку; для фиксированной страницы отдельный модуль рассчитывает видимые части всех попадающих в окно листов и заранее загружает два следующих. Локальное смещение скана отделено от серверного номера страницы.

Стартовая сова — один спрайт 22 × 32 на символьной сетке. Каждый знак хранит роль цвета, две строки точек образуют ячейку терминала. Kitty и Alacritty выводят одинаковые полублоки. Для темы Terminal используются слоты ANSI.

Оформление терминала использует SGR по умолчанию и ANSI; только непрозрачная бумага требует актуального RGB через OSC 11. Именная палитра интерфейса независима от бумаги книги. Здесь нет привязки к pywal или matugen. У каталога собственное дерево с независимыми группами; карточка грузит метаданные в фоне, не сдвигая область клика по файлам. Смена статуса и сброс используют разные API и не подменяются записью произвольного процента.

Сверено с [режимами Bookokrat](https://bugzmanov.github.io/bookokrat/index.html), [нативным API книг BookOrbit](https://github.com/bookorbit/bookorbit/blob/6ad1445dab35757164ed3bf31e83caeb6ba24ad2/server/src/modules/book/book.controller.ts), [транзакцией сброса](https://github.com/bookorbit/bookorbit/blob/6ad1445dab35757164ed3bf31e83caeb6ba24ad2/server/src/modules/reading-state/reading-state.repository.ts) и [спецификацией OPDS 2](https://specs.opds.io/opds-2.0.html). Границы совместимости и проверок — в [чеклисте](checklist.ru.md).

В локальной библиотеке дерево читает только непосредственные подпапки раскрытой ветки. Прямой переход по пути раскрывает его родителей. Поиск по всему корню — отдельная фоновая операция; перетаскивание границы отвечает только за геометрию обеих панелей.

Графические заглушки сохраняются в `$XDG_CACHE_HOME/botui/jackets-v1` (или `~/.cache/botui/jackets-v1`), не более 512 изображений. Ключ учитывает рисунок и метаданные; повреждённый файл создаётся заново. При наличии fontconfig используется его индекс шрифтов, иначе — обычный поиск системных шрифтов. Обе операции выполняет существующий фоновый поток.

SVG-иллюстрации EPUB (встроенные и подключённые через `img`/`object`) используют тот же кэш рисунков. Модуль форматов упаковывает ссылки на изображения внутри архива, а модуль фиксированных изображений рисует SVG через уже используемый resvg в фоновых задачах. При вёрстке читаются только размеры, без шрифтов и отрисовки контуров. Белая подложка сохраняет читаемость чёрных линий SVG на тёмных темах.
