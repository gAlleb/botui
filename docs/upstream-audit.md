# Что BOTUI перенимает у Bookokrat и BookOrbit

Сверка исходников 7 ноября 2026 года. BOTUI сохраняет один ридер для всех источников. Источник отвечает за каталог, получение файла и доступную серверную синхронизацию; расположение текста или скана вычисляет ридер.

[Справка Bookokrat](https://github.com/bugzmanov/bookokrat/blob/9c02ee3b3a0f86791b3917cb1a93436d92a8603e/src/widget/help_popup.rs) превращает большой список команд в отдельный доступный для поиска экран. В BOTUI разделы строятся из собственных команд с учётом открытого ридера; оформление работает и на узкой сетке терминала.

В EPUB отдельно проверен случай, когда примечание находится в конце книги и открытие последней главы не означает завершения чтения. Временный переход хранит исходный адрес текста: возврат, изменение размеров и выход из книги не подменяют его адресом словаря.

## Открытые различия

- Для нативных заглушек реализован Bauhaus; альтернативные стили веб-профиля пока не импортируются.
- Для PDF и DjVu поиск указывает лист с фрагментом текста. OCR и подсветка отдельных глифов на скане не реализованы.
- Заметки привязаны к месту чтения. Произвольное выделение диапазона текста и обмен такими выделениями с веб-клиентом — отдельная функция.
- Парсер EPUB/FB2 показывает текст, таблицы, ссылки и растровые иллюстрации. Он не является браузерным движком для полного CSS, MathML или воспроизведения аудио и видео.
- Нет оснований считать любой локальный адрес взаимозаменяемым с CFI или координатами другого издания. Сквозной тест веб → физический iPhone → BOTUI для того же файла остаётся открытым.
